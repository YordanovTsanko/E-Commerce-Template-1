# Магазин — онлайн магазин (MERN)

Пълнофункционален онлайн магазин за облекло, обувки, електроника, бижута и фитнес аксесоари. Изграден е със стека **MongoDB · Express · React · Node.js**. Проектът покрива целия път на клиента: разглеждане на каталога, търсене, количка, поръчка и ревюта. Има и отделен админ панел за управление на продукти, поръчки и потребители.

**Демо:** [project-1-henna-tau.vercel.app](https://project-1-henna-tau.vercel.app)

## Възможности

### За клиента
- **Каталог по категории** с подреждане по най-нови, цена (възходящо/низходящо) и оценка.
- **Търсене в реално време** по име, описание и категория. Заявката се изпраща след кратка пауза в писането, за да не натоварва сървъра.
- **Страница на продукта**: наличност, избор на количество, споделяне и ревюта със звездна оценка.
- **Ревюта**: добавяне, редакция и изтриване на собствено ревю. Средната оценка на продукта се преизчислява автоматично.
- **Количка**, която се пази в профила и е достъпна от всяко устройство.
- **Поръчка в три стъпки**: количка, данни за доставка, потвърждение. Плащането е с наложен платеж, а доставката е безплатна над определена сума.
- **Профил**: лични данни, адрес за доставка, смяна на парола и история на поръчките.
- **Регистрация и вход** със сесия, валидиране на формите и изисквания за силна парола.

### За администратора
- **Табло** с оборот, брой поръчки, продукти и потребители, графика на продуктите по категория и поръчките по статус.
- **Продукти**: списък с търсене и филтър, добавяне с валидиране, преглед и изтриване.
- **Поръчки**: таблица с търсене по клиент, имейл или град, филтър по статус и странициране.
- **Потребители**: списък с роли и дати на регистрация.
- Отделен изглед без навигацията на сайта, с бутон „Обратно към сайта“.

### Потребителско изживяване
- Адаптивен дизайн за телефон, таблет и компютър.
- Скелетони по време на зареждане, известия (toast) за успех и грешка, празни състояния с ясно следващо действие.
- Грешките от сървъра се показват на разбираем български.
- Собствена страница 404, достъпни елементи (фокус от клавиатура, aria етикети) и поддръжка на `prefers-reduced-motion`.

## Архитектура

```
┌─────────────────────┐   HTTPS + сесийна бисквитка   ┌─────────────────────┐        ┌──────────────┐
│  React (Vercel)     │ ─────────────────────────────▶ │  Express API        │ ─────▶ │ MongoDB Atlas│
│  Redux · Axios      │ ◀───────────────────────────── │  (Render)           │ ◀───── │              │
└─────────────────────┘          JSON                  │  Passport · Session │        └──────────────┘
                                                       └─────────────────────┘
```

- **Автентикация:** входът минава през Passport Local Strategy. След това сесията се пази в `httpOnly` бисквитка. Фронтендът изпраща всички заявки с `withCredentials: true`, а бекендът допуска само адресите от `CLIENT_URL`.
- **Роли:** `user` и `admin`. Админ маршрутите са защитени и на двете места: от middleware `isAuthenticated` и `isAdmin` в бекенда и от `AdminRoute` в React.
- **Състояние:** Redux пази профила, количката, продуктите, поръчките и ревютата. Единствената Axios инстанция в `src/api/axios.js` държи адреса на API-то и превежда грешките.

## Стартиране локално

**Изисквания:** Node.js 18+ и база в MongoDB Atlas (или локален MongoDB).

### 1. Бекенд
```bash
cd backend
npm install
cp .env.example .env      # попълнете стойностите (виж по-долу)
npm start                 # http://localhost:5555
```

### 2. Фронтенд
```bash
cd frontend
npm install
cp .env.example .env
npm start                 # http://localhost:3000
```

### 3. Администратор
Регистрирайте се през сайта, след което в MongoDB сменете полето `role` на вашия потребител на `"admin"`. Ще се появи бутон „Админ панел“. От страницата с продукти можете да добавите 10 тестови продукта с един клик.

## Променливи на средата

### `backend/.env`
| Променлива | Описание | Пример |
|-----------|----------|--------|
| `DB_MONGO` | Връзка към MongoDB | `mongodb+srv://user:pass@cluster.mongodb.net/` |
| `NODE_ENV` | `DEVELOPMENT` или `PRODUCTION` | `DEVELOPMENT` |
| `PORT` | Порт на сървъра | `5555` |
| `SESSION_SECRET` | Дълъг случаен низ за подписване на сесията | — |
| `CLIENT_URL` | Адресите на фронтенда, разделени със запетая | `http://localhost:3000,https://project-1-henna-tau.vercel.app` |

### `frontend/.env`
| Променлива | Описание | Пример |
|-----------|----------|--------|
| `REACT_APP_API_URL` | Адрес на бекенда, без `/` накрая | `http://localhost:5555` |

Данните на магазина (име, телефон, имейл, цена на доставката, валута) са в `frontend/src/config/site.js`.

## API

Всички маршрути са под `/api/v1`. 🔒 = изисква вход, 👑 = изисква роля `admin`.

### Автентикация и профил
| Метод | Маршрут | Описание |
|-------|---------|----------|
| POST | `/register` | Регистрация |
| POST | `/login` | Вход |
| POST | `/logout` | Изход |
| GET | `/isloggedin` | Текущ потребител |
| PUT | `/user/edit/:id` 🔒 | Редакция на профил или смяна на парола |

### Продукти
| Метод | Маршрут | Описание |
|-------|---------|----------|
| GET | `/products/:category` | Продукти в категория |
| GET | `/products/:category/:id` | Един продукт |
| GET | `/product/search/:text` | Търсене |

### Количка и поръчки 🔒
| Метод | Маршрут | Описание |
|-------|---------|----------|
| GET | `/cart` | Съдържание на количката |
| PUT | `/cart/add/:productId` | Добавяне на 1 брой |
| DELETE | `/cart/delete/:productId` | Премахване |
| POST | `/order/new` | Нова поръчка |
| PUT | `/order/clear/cart` | Изчистване на количката след поръчка |
| GET | `/orders` | Моите поръчки |
| GET | `/order/:id` | Детайли за поръчка |

### Ревюта
| Метод | Маршрут | Описание |
|-------|---------|----------|
| GET | `/review/:productId` | Ревюта за продукт |
| POST | `/review/new` 🔒 | Ново ревю |
| PUT | `/review/edit/:id` 🔒 | Редакция (само на собствено ревю) |
| DELETE | `/review/delete/:id` 🔒 | Изтриване (само на собствено ревю) |

### Администрация 👑
| Метод | Маршрут | Описание |
|-------|---------|----------|
| GET | `/admin/products` | Всички продукти |
| GET | `/admin/product/:id` | Един продукт |
| POST | `/admin/product/new` | Нов продукт |
| DELETE | `/admin/product/delete/:id` | Изтриване на продукт |
| POST | `/admin/random/products` | 10 тестови продукта |
| GET | `/admin/orders` | Всички поръчки |
| GET | `/admin/users` | Всички потребители |

## Публикуване

### Бекенд → Render
1. Създайте **Web Service** от папка `backend` със start command `node server.js`.
2. Задайте променливите от `backend/.env` с `NODE_ENV=PRODUCTION`. В `CLIENT_URL` сложете адреса от Vercel.
3. В продукция бисквитката се изпраща със `SameSite=None; Secure`, защото фронтендът и бекендът са на различни домейни.

### Фронтенд → Vercel
1. Импортирайте папка `frontend` като проект Create React App.
2. В **Settings → Environment Variables** задайте `REACT_APP_API_URL` с адреса от Render.
3. `vercel.json` пренасочва всички адреси към `index.html`, така директни линкове като `/admin/dashboard` работят.

> Някои браузъри (например Safari) блокират бисквитки между различни домейни. За най-стабилна работа насочете фронтенда и бекенда към поддомейни на един и същ домейн, например `shop.bg` и `api.shop.bg`.

## Сигурност

- Паролите се хешират с bcrypt и никога не се връщат в отговорите на API-то.
- Сесийната бисквитка е `httpOnly`, с `Secure` и `SameSite` според средата.
- CORS допуска само адресите от `CLIENT_URL`.
- Админ маршрутите изискват роля `admin` на сървъра, не само в интерфейса.
- Потребителят може да редактира само собствения си профил, без да променя ролята си.
- Текстът за търсене се ескейпва, преди да стане регулярен израз.
- Файлът `.env` не се качва в Git. Ползвайте `.env.example` като шаблон.
